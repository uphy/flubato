# タブ譜 → alphaTex → .gp

譜面を AI が読み、テキストの alphaTex に書き、機械的な検査と原本との見比べで直してから .gp に書き出す。
**.gp を直接作らない。** テキストなら AI が部分的に直せ、人も読めて、git で差分が見える。

原本によって、弦とフレットの取り方が2通りある。

| 原本 | 弦・フレット | リズム | 例 |
|---|---|---|---|
| **文字入りの PDF**（Power Tab・Guitar Pro などが書き出した市販譜） | `pdftab.py` が PDF の文字の座標から機械的に取る。読み違いが無い | 五線を AI が読む | Tommy Emmanuel「Angelina」（8ページ・58小節） |
| **印刷譜のスキャン**（OCR 付きでも数字は化けている） | AI が小節ごとの画像から読む（`pdftab.py --no-text` が切り出す） | 五線を AI が読む | Hal Leonard「Best of Tommy Emmanuel」の「Blue Moon」（6ページ・83小節） |
| **手書き**（スキャン・写真） | AI が画像から読む | 符尾・連桁を AI が読む | 耳コピの手書き譜（5ページ・147小節） |

```
文字入り PDF ─ pdftab.py → listing.txt（小節ごとの音の列）+ mNNN.png（小節の画像）─┐
画像 ─ crop.py → 段ごとの画像（全体・左半分・右半分）──────────────────────────────┤
                                              AI が読む → 分担ごとの .atex（voice1 = メロディ / voice2 = ベース）
                                              ─ check.mjs → 各小節・各声部が拍子どおりの長さか
                                              ─ render.mjs → .png / .gp ─ 原本と見比べる
                                              ─ merge.py → 曲.atex ─ check.mjs ─ render.mjs → 曲.gp
```

## 準備

スクリプトは `scripts/` にある。flubato 本体とは依存を分けてある（PNG の描画に使う alphaSkia が OS ごとのパッケージを要り、本体の CI を壊すため）。

```sh
cd .claude/skills/tab-to-gp/scripts && npm ci   # 初回だけ
python3 -c "import PIL"                        # crop.py / compare.py / pdftab.py が Pillow を使う
which pdftotext pdftoppm                       # pdftab.py が使う（brew install poppler）
```

作業ディレクトリは曲ごとに1つ作る（リポジトリの外、`/tmp/曲名` など）。以下 `$T` は `scripts/` の絶対パス。

- zip で渡されたら、ファイル名が CP932 のことがある。Python の `zipfile` で `name.encode('cp437').decode('cp932')` して取り出す
- Google Drive などから来た名前は NFD（濁点が別の文字）のことがある。出力の名前は NFC にそろえる
- この環境の PreToolUse フックは、`cd X && ...` のように連結した Bash コマンドで誤作動することがある。絶対パスを使い、コマンドを分ける

## 手順

### 1. 原本の種類を見分け、曲の約束事を決める

PDF なら、まず文字が入っているかを見る。

```sh
pdftotext -layout score.pdf - | head -80
```

TAB の数字が並んで出てくれば **文字入り PDF**（手順 2A）。何も出ないか文字化けなら **画像**（手順 2B）として扱う。

- スキャンに OCR をかけた PDF（`pdfinfo` の Producer が ABBYY FineReader など）は、文字が入っていても数字が化けている（キリル文字や記号になる）。画像として扱う
- 印刷譜のスキャンなら、`pdftab.py --no-text` で線と小節線だけを画像から探し、小節ごとの画像を作れる（手順 2A の出力から listing の音を除いたもの）。手書き譜より小節の区切りがはっきりしているので、こちらを使う
- 曲集は目次のページ番号と PDF のページ番号がずれる。サムネイルを並べて、曲の最初と最後の PDF ページを確かめてから `--pages 8-13` で絞る。同じフォルダに曲名の PDF が別にあっても、中身（出版社・採譜者）が違うことがあるので、頼まれた方を使う

縮小画像（`sips -Z 1500`）で全ページを見て、次を決めてから読み始める。分担して並行に読むとき、各担当に同じ前提を渡すため。

- **チューニングとカポ**: TAB 線の左端か譜面の冒頭に書いてある（`TUNING: "DROPPED D"`、`CAPO 2nd FRET` など）。**書いていなければ標準チューニング**
- **拍子とテンポ**: 印刷譜は冒頭に書いてある。手書き譜は書かれていないことが多く、1小節の上向き符尾の数と連桁のまとまりから推定する
- **曲名・アーティスト**: ページ上部
- **記号**: 下の対応表に無い記号を拾っておく
- 原曲の音源があれば在り処をメモする（リズムの確認は人が耳でするため）

### 2A. 文字入り PDF: 音を機械的に取り出す

```sh
python3 $T/pdftab.py score.pdf out --tuning "E4 B3 G3 D3 A2 D2"   # 1弦から。標準なら省略
python3 $T/pdftab.py book.pdf out --pages 8-13 --no-text           # 曲集の1曲、OCR の化けたスキャン
```

- TAB の横線（6本）と五線（5本）と小節線は、ページ画像（300dpi）から探す。数字は PDF の文字の座標から、どの線に載っているかで弦を決める
- 小節番号は段の左端の数字から取る。番号が振り直されている譜面（Power Tab は最終ページで 1 に戻ることがある）では、通し番号を続ける
- `out/listing.txt` の1小節はこう出る。横位置は小節内の 0〜1、`[ ]` は五線での書き音（実音の1オクターブ上。カポは数えない）で、五線の符頭と TAB の数字を対応付けるのに使う

```
m32  [p5 s1]  m032.png
  0.14  7.3                    [D5]
  0.33  (5.1 7.3)              [A5 D5]   // 小さい数字（装飾音か）: 1弦 3弦
  0.52  (5.1 6.3)              [A5 C#5]   // 括弧: 3弦
  0.71  x.6                    [x]
  注記: "let"@0.12上 "ring"@0.16上 "H"@0.36下 "P"@0.45下
```

- `out/mNNN.png` は小節ごとの画像（五線 + TAB）、`out/pN-sM.png` は段ごとの画像
- **弦とフレットは listing のとおりに書き、変えない。** AI が決めるのは、リズム（五線の音価・連桁・付点・休符・3連符）、声部の振り分け（符尾の向き）、奏法記号
- 1列には、横位置がほぼ同じ数字がまとめて入る。装飾音と本体の音が同じ列に入ることがあるので、「小さい数字」の弦だけを装飾音にする
- 拍子の変更は取り出さない。五線の拍子記号を見る（Angelina は m24・m43 だけ 2/4）

### 2B. 画像: 段を切り出す

```sh
python3 $T/crop.py 01.jpg p01    # p01-s1.png … と、左右半分の p01-s1-L.png / -R.png
```

ページ画像は `01.jpg` `02.jpg` … の名前で置く。6本の横線のまとまりを1段とみなす。線が薄いスキャンは閾値を自動で緩める。**数字は必ず半分の画像で読む**（全体画像は小節線と連桁の把握用）。

### 3. 分担して alphaTex を書く

分担を **1担当 = 約15小節（文字入り PDF）/ 1ページ（画像）** にし、Agent の fork で並行して読ませる。各担当には、手順1で決めた約束事と、この節の形式・規則、下の対応表をそのまま渡す。

分担のファイルは単体でコンパイルできる形にし、声部の区切りに決まったコメントを入れる（`merge.py` がこれで切り分ける）。

```
\title "曲名 part1"
\tempo 64
\tuning E4 B3 G3 D3 A2 D2
\capo 2
.
\ts 4 4
// === voice1 ===
\voice
// m1
12.1.8 10.2.8 ... |
// === voice2 ===
\voice
// m1
0.5.4 {d} r.8 ... |
```

- 小節ごとに行を分け、行頭に位置のコメントを付ける。人が原本の位置を探すときに使う。文字入り PDF は `// m32`（原本の小節番号）、画像は `// p<ページ>-s<段>-m<段内の小節>`
- voice1 = 上向き符尾（メロディ）、voice2 = 下向き符尾（ベース）。**両声部の小節数をそろえる。** 音の無い区間は休符で埋める。同じ瞬間に両声部の音があるときは、listing の和音を声部ごとに分ける
- 符尾が全部上向きのページは voice1 に全部入れ、voice2 を休符で埋める
- 弱起（冒頭の不完全小節）も、原本が休符付きの完全小節で書いていればそのとおり休符で埋める
- 自信の無い箇所は行末に `// ?` と理由を書く。**分からない記号を推測で消さない**
- 意味の決まっていない記号（丸囲みの数字など）は普通の音として書き、行末に印（`// ○`）を付ける
- Bash は絶対パスで単独のコマンドにする（担当にも伝える。上の「準備」を参照）

### 4. 検査して、原本と見比べる

```sh
node $T/check.mjs part1.atex          # NG 0 になるまで直す
node $T/render.mjs part1.atex 2400    # part1.png と part1.gp
python3 $T/compare.py p01-s1.png p01.png cmp.png 60 420   # 画像のとき。上下に並べる
```

- `check.mjs` は各小節・各声部の長さを拍子と比べる。装飾音（`{gr}`）は数えない
- 長さが合わないときは、まず付点・3連符・休符の読み落としを疑う。音価の推定で合わせたら `// ?` を付ける
- 見比べは最低1往復
  - 画像のとき: **弦の読み違い（1本ずれ）が一番多い。** 手書きの数字は線の上ではなく線と線の間に書かれがちで、半分画像を等倍で見ても1弦ずれる。怪しい段は拡大して読み直す
  - 文字入り PDF のとき: 弦は正しいので、声部の振り分けと音価を見る
- 同じ形の小節（繰り返し）は読み取りの答え合わせに使える

### 5. 1曲にまとめる

```sh
cat > header.atex <<'EOF'
\title "曲名"
\subtitle "アーティスト / 採譜: 名前"
\tempo 64
\tuning E4 B3 G3 D3 A2 D2
\capo 2
.
\ts 4 4
EOF
python3 $T/merge.py header.atex song.atex part1.atex part2.atex ...
node $T/check.mjs song.atex
node $T/render.mjs song.atex 2400
```

`merge.py` は分担の末尾で省かれた小節線 `|` を補う。**補わないと、前の分担の最後の小節と次の分担の最初の小節が1小節につながる**（分担単体では検査を通るので気付かない）。

### 6. 人に渡す

- **出力は原本と同じフォルダに、原本と同じ名前で置く**（`Angelina.pdf` → `Angelina.gp` と `Angelina.atex`）。曲集の1曲は `曲名 (曲集名).gp`（例 `Blue Moon (Best of Tommy Emmanuel).gp`。同じ曲の別の採譜と並んでも区別できる）。同じ名前のファイルがあれば上書きせず、人に聞く。作業ディレクトリ（`/tmp/...`）に置いたままにしない
  - `.gp` は TuxGuitar 2.1 / Guitar Pro / flubato で開ける。`.atex` は正本で、直すならこちら
- **報告の冒頭に `.gp` の絶対パスをコードブロックで書き、`open -R <パス>` で Finder に出す。** どこにできたか分からない、と言われたため
- 報告に書くこと: 小節数、`check.mjs` の結果、`// ?` と `// ○` の件数と主な中身、alphaTex で表せなかった記号の一覧
- **リズムは原曲と聴き比べてもらう。** 手書き譜はリズムが省かれていることが多く（旗も連桁も無い4分の符尾だけ、など）、画像からは決まらない。印刷譜は五線に書いてあるので決まるが、読み違いは残りうる
- 記号の意味を教えてもらえたら、下の対応表を更新する

## alphaTex の書き方

| 書きたいこと | 書き方 | 注意 |
|---|---|---|
| 音 | `フレット.弦.音価` | 弦は一番上の線 = 1弦 |
| 和音 | `(7.1 7.2 0.6).4` | |
| 付点 | `.8 {d}` | 拍の効果として音価の後に書く |
| 休符 | `r.8` | |
| 3連符 | 各音に `{tu 3}` | |
| タイ | `-.弦`（和音の中なら `(-.1 2.3)`） | 直前の拍に無くても、さかのぼって同じ弦の音につなぐ。分担の頭で前の分担の音につないでもよい |
| 装飾音 | `8.1{gr}` | `check.mjs` は長さに数えない。小節は装飾音を除いて拍子どおりにする |
| ハンマリング・プリング | 元の音に `{h}` | |
| スライド | 元の音に `{sl}` | |
| 自然ハーモニクス | `12.1{nh}` | |
| デッドノート | `x.6` | |
| レットリング / パームミュート | 音に `{lr}` / `{pm}` | |
| アルペジオ | 拍に `{ad}` / `{au}` | |
| カポ | ヘッダに `\capo 2` | |
| 声部 | `\voice` | 全小節の voice1 を書いてから、全小節の voice2 |
| 拍子の変更 | 小節の頭に `\ts 3 4` | voice1 にだけ書く |
| 反復 | `\ro` … `\rc 2`、括弧は `\ae (1)` | |

## 記号の対応表

### 印刷譜（Power Tab の書き出し）

| 記号 | alphaTex | 状態 |
|---|---|---|
| 括弧付きの数字 `(0)` | 五線でタイがつながっていれば `-.弦`。つながっていなければ `{g}` + `// ?` | タイは確定（Power Tab はタイの後ろの音を括弧で書く）。タイ元の無い括弧は Angelina に約20か所あり、ゴーストノートと推定 |
| 小さい数字 | 装飾音 `{gr}` | 確定 |
| 角括弧の数字 `[12]` + N.H. | `{nh}` | 確定 |
| `x` | `x.弦` | 確定 |
| H / P（TAB の下） | 元の音に `{h}` | 確定 |
| sl.（TAB の下） | 元の音に `{sl}` | 確定。ただし行き先が別の弦なら書かない（`{sl}` は同じ弦の次の音まで線を引くため、離れた音までの長いスライドになる）。行き先が無ければ `{sod}` |
| let ring / P.M. | `{lr}` / `{pm}` | 確定 |
| 15mb / 8vb | 書かない | 五線のオクターブ記号。TAB には影響しない |
| rit. | コメント | |

### 手書き譜

手書き譜の記号は書き手ごとに違う。**確定したものだけを「確定」にする。**

| 手書きの記号 | alphaTex | 状態 |
|---|---|---|
| H / P / 音と音をつなぐ弧線 | 元の音に `{h}` | 確定 |
| s / 数字の前の斜線（前の音から） | 元の音に `{sl}` | 確定 |
| s / 斜線（下から入る） | `{sib}` | 確定 |
| 菱形 + 括弧 `7(19)`（タップハーモニクス） | `7.2{th 12}` | 確定。**値は叩く位置 − 押さえるフレット**（`{th 19}` と書くと <26> になる） |
| × の符頭 | `x.弦` | 確定 |
| 3 と書いた括弧 | `{tu 3}` | 確定 |
| Ras. / 矢印付きの波線（ラスゲアード） | 拍に `{bd}` か `{bu}` | 向きは未確定（上向き矢印 = `{bd}` として扱った） |
| 矢印の無い波線（アルペジオ） | 拍に `{ad}` / `{au}` | 推定 |
| 丸囲みの数字 | 普通の音 + `// ○` | **未確定。** 自然ハーモニクスらしい箇所（12・7・9フレットの高音弦）と、ベースで「3 → ③」とスラーでつながる箇所がある |
| 括弧付きの数字 `(0)` | 普通の音か `{g}` | 未確定。ゴーストノートか、伸ばしている音の再表示 |
| 連桁の上の X / X の付いた符尾 | 書かない（コメント） | 未確定。ゴルペ（胴を叩く）か |
| 「g」「g.」 | `{sl}` | 推定（グリッサンド） |
| K に似た記号、H.C、M、A、四角で囲んだフレット番号 | コメント | 未確定 |
| D.S. / Coda / セーニョ | コメント | alphaTex の記号にはまだしていない。再生は書かれた順に流れる |
| `4:29` のような時刻 | コメント | 原曲の経過時間のメモ |

## 分かっている落とし穴

- **正しさの基準は Guitar Pro と flubato（alphaTab）に置き、TuxGuitar に合わせて .gp を曲げない。** TuxGuitar 2.1 は .gp を開けるが、次のエラーや欠落が出る
  - 小節の途中に装飾音があると「too long」になる。TuxGuitar の読み込みの不具合で、装飾音の拍の長さを直前の拍に書き込んでしまう（`GPXDocumentParser` を逆アセンブルして確認した）。.gp は正しい
  - タイの元の音が同じ声部の直前の拍に無いと「invalid tied note」になる。alphaTab は何拍かさかのぼって同じ弦の音につなぐので、`check.mjs` は通る
  - タップハーモニクスは、押さえるフレットしか表示されない
- **日本語のタイトルは PNG で崩れる**（描画用フォントに字形が無い）。副題は出る。.gp には影響しない
- 分担すると、分担末の小節線の省略と分担をまたぐタイが起きる。`merge.py` の後に必ず曲全体で `check.mjs` を通し、`render.mjs` の画像で継ぎ目の小節を見る
- 担当が長さを合わせるために音価を曲げることがある（装飾音を含めて4拍にした、など）。`check.mjs` を通っても、`// ?` の付いた小節は原本か原曲で確かめる
- `pdftab.py` の小節線は「TAB を縦に貫く線」で探す。全弦に数字が並ぶ和音やアルペジオの波線もこれに当たるので、端の線の外へ短くはみ出すものを数字の列として除いている。それでも段ごとの小節数は、担当に渡す前に原本の段画像と数え合わせる（Blue Moon で誤検出が2か所あり、担当が原本と照らして気付いた）
- `pdftab.py` は PDF の文字を使うので、TAB を図形（線や曲線）で描いた PDF では数字が取れない。その PDF は画像として扱う
- let ring の範囲線、コード名、第3の声部、スタッカートは書いていない（Angelina での扱い）。必要になったら alphaTex の書き方を調べて対応表に足す
- AI の使用量の実測
  - 画像の手書き譜: 1ページの担当で約30〜35万トークン（5ページ・147小節）
  - 文字入り PDF: 15小節の担当で約15万トークン・約7〜8分。4担当の並行で58小節（Angelina）
  - 印刷譜のスキャン: 約20小節の担当で約24〜30万トークン・約4〜5分。4担当の並行で81小節（Blue Moon）
